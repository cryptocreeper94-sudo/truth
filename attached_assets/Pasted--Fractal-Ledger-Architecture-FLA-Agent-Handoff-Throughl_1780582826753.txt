# Fractal Ledger Architecture (FLA) — Agent Handoff

> **Throughline: "Private but Verified."**
> Every record is private to the entity that created it. Every claim is mathematically verifiable by any authorized party. No raw data crosses boundaries — only cryptographic proof.

---

## 1. What is the FLA?

The **Fractal Ledger Architecture (FLA)** is a hub-and-spoke cryptographic trust topology designed by DarkWave Studios LLC (founder: Jason). It solves a fundamental enterprise tension: **divisions need data autonomy, but the enterprise needs assurance.**

The word "fractal" is precise — the same architectural pattern repeats at every level of scope:

```
Enterprise → Division → Facility → Asset
```

Each node at every level is a self-similar replica of the whole system. This is not a monolithic ledger with access controls bolted on. It is a **structurally compartmentalized trust fabric** where isolation is a _mathematical property_ of the topology, not a policy decision.

### Key Properties
- **Not a blockchain.** No tokens, no cryptocurrency, no mining, no gas fees.
- **Not AI.** Deterministic, rules-based. Same input → same output, every time.
- **Proof-of-Authority (PoA)** consensus — each facility operates as a validator node.
- **Hash-only anchoring** — the root never sees raw data, only SHA-256 proof of integrity.
- **Ed25519 cryptographic signatures** on all certificates.

---

## 2. The Three-Layer Stack

The FLA has exactly three layers. Every deployment (Cox, government, or future clients) follows this pattern:

```
┌─────────────────────────────────┐
│         CORE Root Fabric        │  ← Universal trust anchor
│   (hash-only, zero data exposure)│
├─────────────────────────────────┤
│      Private Ledger (per div)   │  ← Internal operational records
│   (full data, compartmentalized) │
├─────────────────────────────────┤
│   Verification Ledger (per div) │  ← External proof layer
│  (certificates, public-facing)   │
└─────────────────────────────────┘
```

### Layer Naming by Deployment

| Layer | Cox (CEP) | Government (Gov-Site) | Generic |
|-------|-----------|----------------------|---------|
| **Root Fabric** | CORE | CORE | CORE |
| **Private Ledger** | CAL (Cox Automotive Ledger) | APL (Agency Private Ledger) | Private Ledger |
| **Verification Ledger** | VET (Verified Enterprise Trust) | AVL (Agency Verification Ledger) | Verification Ledger |
| **Architecture Name** | FLA | FLA | FLA |

> [!IMPORTANT]
> **CORE is universal** — it is the same acronym and concept on every deployment. It stands for "Certified Operational Record Engine." It is NOT a Cox-specific term. Both Cox and government builds use CORE as the root.

## 3. How Data Flows

```
Raw Event (OBD-II scan, lot move, custody transfer, field report)
    │
    ▼
Private Ledger (CAL or APL)
    │  Sealed immediately with SHA-256 hash + Ed25519 signature
    │  Full operational data stored here — never leaves this ledger
    │
    ▼
Verification Ledger (VET or AVL)
    │  Issues verifiable certificates to external parties
    │  Contains: certificate ID, hash, timestamp, status
    │  Does NOT contain raw operational data
    │
    ▼
CORE Root Fabric
    │  Receives hash anchors from all division ledgers
    │  Never sees raw data — only cryptographic proof
    │  Provides cross-division integrity verification
    └── "Did this event happen?" → Yes/No (mathematically provable)
```

### The Key Insight
A breach of one division's ledger **cannot propagate** to any other division or to CORE. Each dual-ledger pair is cryptographically isolated. CORE only stores hashes — even if CORE were compromised, no operational data would be exposed.

### TypeScript Strictness
All three builds use **strict TypeScript** with `tsc -b` before Vite build. This means:
- Unused imports → **build failure** (TS6133)
- Type mismatches → **build failure** (TS2367)
- Missing exports → **build failure**

Always run `npx vite build` locally before pushing to catch these.

1. **FLA is the canonical acronym.** Use it in all new text. Spell out "Fractal Ledger Architecture (FLA)" on first mention, then "FLA" after.
2. **CORE is universal.** Never rename it per-deployment. Both Cox and Gov use CORE.
3. **CAL/VET are Cox-only.** Never use on gov-site. Use APL/AVL instead.
4. **APL/AVL are Gov-only.** Never use on CEP. Use CAL/VET instead.
5. **"Private but Verified"** is the throughline for all marketing, narration, and pitch copy.
6. **No AI claims.** The platform is deterministic, not AI-powered. Explicitly say "not AI" when relevant.
7. **No blockchain/crypto language.** Say "ledger" not "blockchain." No tokens, no mining.
8. **Build locally before pushing.** `npx vite build` catches TS errors that will fail on Render.
9. **Lot Ops Pro is integrated into COP Desktop** — no separate .exe needed.
10. **LumeScan** is the diagnostic hardware/app layer (42 OBD-II PIDs, condition certificates).
