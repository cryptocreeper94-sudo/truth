## 1. SCOPE OF CHANGE

The Axiom Deterministic AI (DDA) knowledge engine was upgraded from a static pattern-response lookup architecture to a dynamic deterministic Natural Language Generation (NLG) pipeline. This change affects how responses are composed at runtime while preserving all existing knowledge data and deterministic guarantees.

**Systems Affected:** DDA Engine (`D:\dda`)
**Systems NOT Affected:** Trust Layer SSO, Firebase Auth, Axiom Studio IDE, Lume-Cortex OS, Arbora Platform

---

## 2. PROBLEM STATEMENT

The prior architecture matched user queries via regex patterns and returned pre-written ("canned") text responses from 212 domain packs containing ~181,000 topics. This created two issues:

1. **Stale Responses** — Every query on the same topic returned the identical verbatim paragraph, producing a robotic feel that contradicted the product's "live" conversational goal.
2. **No Learning** — The system could not incorporate new knowledge, user corrections, or conversational preferences without manually editing pack source files.

## 4. ARCHITECTURE — BEFORE vs AFTER

### Before (Static Lookup)
```
User Input → Regex Match → Return pre-written paragraph verbatim
```

### After (Deterministic NLG Pipeline)
```
User Input
  → Intent Classification (unchanged)
  → Knowledge Engine match (unchanged)
  → Response text parsed into structured fact:
      { subject, core, process, goal, aspects, keywords }
  → Grammar template selected by intent type (DEFINE, EXPLAIN, etc.)
  → Template slots filled with fact fields
  → Synonym variation applied (deterministic, hash-seeded)
  → Tone register applied (auto-detected from query style)
  → Learning preferences applied (corrections, preferred terms)
  → Final composed response returned
```

---

## 5. DETERMINISM GUARANTEE

The synonym variation engine uses a deterministic seed derived from `hash(query)`. This means:

- **Same input → Same output, every time.** No randomness. No probability.
- **Different inputs → Different phrasing.** "What is X" and "Explain X" produce different but factually equivalent responses.
- **Verified:** Determinism test passed — 100 identical queries produced 100 identical responses.

No stochastic models, no LLM calls, and no external API dependencies are introduced by this change. The engine remains fully offline-capable.

---

## 6. LEARNING SYSTEM

Five persistent learning dimensions were added:

| Dimension | Trigger | Storage | Persistence |
|-----------|---------|---------|-------------|
| Alias Learning (pre-existing) | `teach()` API | `learned_aliases.json` | Disk |
| Fact Learning | "Remember that..." / "Learn this..." | `learned_facts.json` | Disk |
| Correction Learning | "Actually..." / "That's wrong..." | `learned_corrections.json` | Disk |
| Preference Learning | "I prefer..." / "Be more concise" | `learned_preferences.json` | Disk |
| Conversation Context | Automatic (turn tracking) | In-memory | Session only |

All disk-persisted learning survives server restarts. Learning data is stored as plain JSON in `src/knowledge/`.

---

## 7. BACKWARDS COMPATIBILITY

- The `cognitive-engine.js` integration uses a try/catch wrapper: if the new CompositionEngine fails for any reason, it falls back to the original `_applyMode()` legacy behavior silently.
- The knowledge engine's `query()` method return schema is unchanged — existing consumers receive the same `{ domain, intentKey, answer }` object.
- The `conversation.js` pack (greetings, feelings, time, jokes) continues to use its existing dynamic response functions and is not routed through the CompositionEngine.
