------------------------------------------------------------
I. SYSTEM OVERVIEW
------------------------------------------------------------
AXIOM is a deterministic reasoning engine. It does NOT require full knowledge corpora to operate. It only requires:

1. Deterministic runtime (local)
2. Pattern matcher + rule engine (local)
3. Micro‑Knowledge Cache (local)
4. Cloud Knowledge Packs (remote, streamed)
5. Synthetic Organism Interface Layer (local)
6. Pack Synchronization Protocol (remote → local)

This architecture allows AXIOM to operate:
- Fully offline (reduced capability)
- Partially offline (cached packs)
- Fully online (full canon access)

AXIOM never breaks determinism because all transforms are rule‑based, not probabilistic.

------------------------------------------------------------
II. TIERED KNOWLEDGE SYSTEM
------------------------------------------------------------

TIER 1 — CORE ENGINE (LOCAL, ALWAYS PRESENT)
- Deterministic compiler
- Intent resolver
- Pattern matcher
- Rule executor
- Local reasoning graph
- Safety constraints
- Synthetic organism hooks
- Zero external dependencies
- < 10 MB footprint

This tier allows AXIOM to function offline with basic reasoning.

TIER 2 — MICRO‑KNOWLEDGE CACHE (LOCAL, ROTATING)
- 50–200 compressed Knowledge Packs
- Auto‑evicting LRU cache
- Indexed by pattern signatures
- Updated when online
- Provides 80% of common queries offline

This tier gives offline users meaningful capability without storing the full canon.

TIER 3 — CLOUD KNOWLEDGE PACKS (REMOTE)
- Full canonical packs stored remotely
- Streamed on demand
- Never fully downloaded
- Cached only when used
- Version‑controlled
- Deterministic signatures ensure consistency

This tier prevents shipping gigabytes of data to every device.

------------------------------------------------------------
III. PACK STREAMING PROTOCOL (PSP)
------------------------------------------------------------

AXIOM uses a deterministic streaming protocol:

1. User query triggers pattern match
2. If pack is missing locally:
   - AXIOM requests remote pack header
   - Remote server returns:
     a. Pack signature
     b. Pack index
     c. Pack delta (if needed)
3. AXIOM downloads ONLY the required topic(s)
4. AXIOM stores them in Micro‑Cache
5. AXIOM executes deterministic reasoning

This ensures:
- Minimal bandwidth
- No full pack downloads
- No version drift
- Deterministic behavior across devices

------------------------------------------------------------
IV. OFFLINE MODE BEHAVIOR
------------------------------------------------------------

When offline, AXIOM operates in three modes:

MODE A — FULL OFFLINE
- Only Tier 1 + Tier 2 available
- No cloud access
- AXIOM uses:
  - Local patterns
  - Local rules
  - Local cached packs
- If a pack is missing:
  - AXIOM returns deterministic fallback response
  - AXIOM logs “missing pack signature” for later sync

MODE B — PARTIAL OFFLINE
- Device has cached packs from previous sessions
- AXIOM can answer most queries
- Missing packs are queued for sync

MODE C — SYNC MODE (when connection restored)
- AXIOM uploads missing signatures
- Server returns deltas
- Micro‑Cache updates
- Deterministic parity restored
