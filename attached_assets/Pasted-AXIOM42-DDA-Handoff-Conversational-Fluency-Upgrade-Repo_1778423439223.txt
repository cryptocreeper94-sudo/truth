AXIOM42 (DDA) — Handoff: Conversational Fluency Upgrade
Repo: github.com/cryptocreeper94-sudo/DDA
Date: May 10, 2026

GOAL
----
Axiom is a deterministic AI engine with 149 knowledge domain packs (~181,000 facts).
It does NOT use an LLM by default. When a user asks a question, the engine pattern-matches
against its knowledge packs and returns the stored fact verbatim through a template system.

The problem: these deterministic responses sound robotic and often wrong. Example:

  User: "What is code"
  Axiom: "Now that's a fun one. code auditing refers to the applied science of building,
  optimizing, and governing systems that implement code auditing."

Three failures: wrong match ("code" hit "code auditing"), circular definition (defines
itself using itself), and a forced personality prefix ("Now that's a fun one.").

We want Axiom to sound like a knowledgeable person having a real conversation — while
still grounding every answer in its verified knowledge packs. No hallucination, but
no robot voice either.

WHAT WE CHANGED (commit d31bf37, 3 files)
------------------------------------------

1. src/conversation/gateway.js — FULL REWRITE
   The LLM gateway previously only supported OpenAI (gpt-4o-mini). We rewrote it to
   support Anthropic Claude as the primary provider with OpenAI as fallback. The gateway
   auto-detects which provider to use based on env vars (ANTHROPIC_API_KEY and
   AXIOM_LLM_PROVIDER). It exposes two methods:
   - generate() — pure conversational LLM (Tier 3, no knowledge context)
   - composeGrounded() — takes verified facts and asks the LLM to compose a natural
     response using ONLY those facts (Tier 1.5 and Tier 2)

2. src/runtime/orchestrator.js — Added "Tier 1.5" polishing
   The speak() method has a tiered response pipeline:
     Tier 1: Knowledge pack hit → raw deterministic answer
     Tier 2: No direct hit → retrieve related facts → LLM composes from facts
     Tier 3: No facts at all → pure LLM with system prompt

   We added Tier 1.5 between 1 and 2. When a knowledge pack returns a direct hit,
   instead of serving the raw text, we now pass it to composeGrounded(). Claude reads
   the deterministic fact and rephrases it into natural conversational speech. The raw
   deterministic answer is preserved in _rawDeterministic for audit. If the LLM call
   fails, it falls back to the raw answer silently.

   Tier 1.5 is skipped for: live data (weather/time), wikipedia results, already-composed
   responses, and meta queries (greetings, farewells, "how do you know that?").

3. src/dpcl/personality.js — Skip forced openers for LLM-composed responses
   The PersonalityEngine used to prepend canned openers to every response:
   "Now that's a fun one.", "Ah, interesting question.", "Buckle up —", etc.
   These are selected deterministically by hashing the input. For LLM-composed
   responses (responseMode === "GROUNDED" or "CONVERSATIONAL"), we now skip prefix
   and suffix injection entirely — Claude already writes with natural conversational
   tone.

EXPECTED RESULT
---------------
Before: "Now that's a fun one. code auditing refers to the applied science of building,
optimizing, and governing systems that implement code auditing."

After: Claude reads the fact and composes something natural like: "Code is the foundation
of all software — it's the set of instructions written in a programming language that
tells a computer what to do. Whether it's Python, JavaScript, or low-level assembly,
code is how everything from mobile apps to operating systems gets built."

The knowledge pack fact is still the source of truth. The audit chain (certHash) still
traces to the original pack entry. The LLM only rephrases — it cannot add information
beyond what the fact contains.

ENV VARS NEEDED ON RENDER (axiom42 service)
--------------------------------------------
ANTHROPIC_API_KEY=sk-ant-api03-... (the Anthropic key)
AXIOM_LLM_PROVIDER=anthropic

Both must be set. ANTHROPIC_API_KEY was added by the owner. AXIOM_LLM_PROVIDER may
still need to be added.

WHAT TO AUDIT
-------------
1. Does gateway.js correctly implement the Anthropic Messages API? Check the x-api-key
   header, anthropic-version header, system field separation, and response parsing
   (data.content[0].text).
2. Is the Tier 1.5 block in orchestrator.js correctly guarded so it only runs on raw
   pack hits and not on live data, wiki, or already-composed responses?
3. Does personality.js skip prefix injection for GROUNDED responses but still apply it
   for raw deterministic responses that were NOT polished (e.g., if the LLM was down)?
4. Is the grounded composition prompt in gateway.js sufficiently constrained to prevent
   hallucination beyond the provided facts?
5. Does the fallback work — if ANTHROPIC_API_KEY is missing or the API errors, does the
   system gracefully serve the raw deterministic answer instead of crashing?
